# Deployment Guide — apple-storefront-clone

This revision (2026-11-27, the `sonnet 5.5 v1` remediation cycle) is rewritten
from the operator's field-tested deployment guide structure with **every claim
re-verified against this codebase** — the prior guide on this branch was
written for the previous Next.js application and none of its facts (Drizzle,
7 tables, 13 API routes, standalone server) applied. Verified truths this guide
is built on: `npm run build` emits exactly one artifact — `dist/index.html`
(512.55 kB, 135.12 kB gzip; CSS 49,567 bytes / 721 rules) — the application makes no
network requests and reads no environment variables at runtime, and the
optional local PostgreSQL 17 is installed rootless by `docs/setup_pg_z.sh`
(Verified accepting connections at `postgresql://postgres:postgres@127.0.0.1:5432/app_db`).

## 1. Supported shape

- One React 19 single-page application: hash routing over 590 enumerated routes
  (home, store + 8 categories + 7 per-category accessories views, the 6 nav-main
  marketing pages (#/mac … #/home), 12 products, bag, entertainment, support,
  552 info pages, 404), TypeScript strict, Tailwind CSS
  v4 CSS-first, built by Vite 7 into **one self-contained HTML file**.
- No backend, no API, no database connection, no auth, no payment provider:
  the bag and last order live in memory; checkout takes no payment and sends
  nothing anywhere. There are no credentials to leak.
- The optional PostgreSQL 17 instance (§4) is the repo family's documented local
  environment — **this application never connects to it**.
- Static assets: `public/sitemap.xml` (590 URLs, generated by `npm run sitemap`)
  and `public/robots.txt` (rendered by the same seam — one `VITE_SITE_URL` stamps both files).

## 2. Prerequisites

- **Node.js ≥ 20** (verified on Node 24). npm is the package manager;
  `package-lock.json` is the lockfile.
- A static file target: `file://`, `vite preview`, an object bucket, or any
  static host (GitHub Pages, Netlify drop, nginx). No Node runtime is needed
  in production.
- Optional (the local database environment): a writable `/home/z/my-project` —
  the rootless install (§4) needs no root and no systemd.

## 3. Install and configure

```bash
git clone https://github.com/nordeim/apple-storefront-clone.git
cd apple-storefront-clone
npm install
npm run dev                 # verify: http://localhost:5173 renders the storefront
```

Environment variables: **none are required.** The app reads no env vars; the
single optional variable drives the sitemap generator:

| Variable | Required | Read by | Notes |
|---|---|---|---|
| `VITE_SITE_URL` | no | `scripts/build-sitemap.mjs` | Base origin stamped into `public/sitemap.xml` AND `public/robots.txt`'s `Sitemap:` directive (both files are written by the same generation run); default `http://localhost:5173/` |

Set it per generation (a shell export beats any `.env`): 

```bash
VITE_SITE_URL="https://your-deploy.example" npm run sitemap
```

**Deployment SEO step (once per origin):** run the generator with your origin
(`VITE_SITE_URL=… npm run sitemap`) — it stamps the `Sitemap:` directive in
`public/robots.txt` and every `<loc>` in the sitemap automatically. The one
remaining manual step is `index.html`'s OG/canonical-ish tags (`og:url`, plus a
`canonical` link if you want one) — point those at the origin too. The
hash-routing SEO posture is documented in `README.md` "SEO" and the PAD's
ADR-007 — crawlers collapse routes onto the entry URL; the sitemap enumerates
the route set for tooling and future path-routing.

## 4. Local database (optional) — rootless PostgreSQL 17 (primary method)

This is the repo family's standard local environment (it also proves the
sandbox can host PostgreSQL for future full-stack work). Idempotent — re-run
safely:

```bash
bash docs/setup_pg_z.sh
```

What the script does (per `skills/rootless-postgresql/SKILL.md`, adapted to
this workspace): resolves the major from apt, extracts the .debs into
`/home/z/my-project/pg/root`, `initdb`s a data dir at `/home/z/my-project/pg/data`
(trust on the socket), enables scram-sha-256 on TCP loopback, starts the
server on **127.0.0.1:5432**, creates `app_db`, and verifies readiness:

```text
postgresql://postgres:postgres@127.0.0.1:5432/app_db   (user postgres, password postgres)
```

Stop/start later with the same binaries:

```bash
/home/z/my-project/pg/root/usr/lib/postgresql/17/bin/pg_ctl \
  -D /home/z/my-project/pg/data -l /home/z/my-project/pg/log/postgres.log stop|start
```

### 4b. Docker alternative

`docker-compose.yml` in this repo runs the same PostgreSQL 17 on the same
loopback contract (credential-matched to the rootless install):

```bash
docker compose up -d        # postgres:17-alpine, app_db, 127.0.0.1:5432 → container :5432
docker compose logs -f postgres
docker compose down         # add -v to DELETE the data volume
```

Health check is built in (`pg_isready -U postgres -d app_db`). Either §4 or §4b
yields the same connection string; choose one (don't run both on 5432 — the
compose file binds loopback only; adjust `ports` if you need a different host
port).

## 5. Build

```bash
npm run build
```

Output: **`dist/index.html`** — one file, everything inlined (verified this
cycle). No other build outputs; `public/` (sitemap, robots) is served
alongside by static hosts that map `public/` → site root (`vite preview` does
this automatically).

## 6. Run / serve

| Target | Command | Notes |
|---|---|---|
| Local preview of the artifact | `npm run preview -- --host 127.0.0.1 --port 4173` | Serves `dist/` exactly as a static host would. Bind `127.0.0.1` — the default `localhost` bind resolves to `::1` on some hosts |
| `file://` | open `dist/index.html` | Works because routing is hash-based; also how `tests/e2e/smoke.mjs` runs |
| Any static host | upload `dist/` (index.html + optional sitemap/robots) | SPA; no rewrite rules needed for hash routing |

## 8. Common issues

| Symptom | Cause | Fix |
|---|---|---|
| Dev page blank; `/src/index.css` → 500 | A stale `postcss.config.*` referencing an uninstalled PostCSS plugin (the replaced Next.js app's leftover) | Delete it — Tailwind runs via `@tailwindcss/vite` (this file's existence is itself a regression; it was removed in this cycle) |
| Build fails "Invalid PostCSS Plugin" | Same root cause | Same fix |
| Playwright webServer timeout | `vite preview` bound to `localhost` → `::1` while the probe hits `127.0.0.1` | Always `--host 127.0.0.1` (the config already does) |
| Dev log: "Failed to run dependency scan … three" | A config re-scanning `skills/**.html` | Keep `optimizeDeps.entries: ["index.html"]` in `vite.config.ts` |
| CSS ballooning / classes you never used appear | Tailwind scanning the vendored prose | Keep the `@source not` set in `src/index.css` |
| Fonts look wide | No SF Pro on the machine | Expected; documented fallback stack |

## 9. Updating an existing deployment

```bash
git pull
npm install
VITE_SITE_URL="https://your-deploy.example" npm run sitemap
npm run build
# re-upload dist/ + public/sitemap.xml + public/robots.txt
```

## 10. Pushing changes to this repository

`main` only; gate green first (§7); push with the SSH wrapper runbook —
`docs/how-to-git-push-using-ssh-wrapper_SKILL.md` — passing this repo's remote
(the wrapper's default remote belongs to the previous project):

```bash
python3 docs/ssh_git_wrapper_v3.py --key-file /tmp/deploy.key \
  --remote git@github.com:nordeim/apple-storefront-clone.git
```

The wrapper verifies the remote ref equals local HEAD after the push and
shreds its temp key; shred the operator key file afterwards per the runbook.
